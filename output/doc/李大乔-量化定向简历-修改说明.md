## 3. 可能被面试官追问的内容

### Akashic Tarot / Python 工程

1. **旧架构具体哪里耦合？** 需要能画出旧版“3D 抽牌后直接保存/解读”和新版“module × input mode × action”的状态流，并说明为什么注册表比前端硬编码更容易扩展。
2. **统一状态机有哪些状态？** 需要区分展示给用户的业务阶段和内部 saving、saved、generating、review 等状态；解释关闭页面、重置草稿和迟到异步响应怎样处理。
3. **为什么选择 Python 标准库 HTTP 服务与 SQLite？** 需要说明项目规模、依赖控制、事务需求和本地隐私目标，也要承认它不是高并发数据平台。
4. **事务原子性怎么实现？** 需要说明 reading、cards、consultation 在同一事务中写入，校验或写入失败为什么不会留下半条数据。
5. **并发保护为什么返回 409？** 需要解释 per-reading 非阻塞锁解决什么问题、锁的粒度，以及它不等于分布式锁。
6. **SSE 中断后为什么保留 partial？** 需要说明调试价值、完整版本与 partial 版本的区分，以及为什么 partial 不进入审核或训练候选。
7. **Fallback 的触发条件是什么？** 需要明确本地模型不可达且已配置 API Key 时才可选择备用后端；不要说所有流式中断都能自动续传或无损切换。
8. **RAG 如何退化？** 需要解释 156 条自建中英语料、card_id 确定性过滤、问题向量重排、索引幂等构建，以及 embedder 不可用时为何退化到 canonical lookup。
9. **trace_id 记录了什么？** 需要能说出每一步的输入摘要、结构化输出、模型、耗时、成功标志，以及为什么不把所有敏感原文无条件暴露给前端。
10. **139 与 14 的口径是什么？** 139 是 Python unittest 项数；14 是 JavaScript 测试文件数，不是 14 项断言，也不代表性能、压力或真实模型端到端测试全部完成。
11. **人工审核和训练数据有什么关系？** 需要说明 accepted/edited、隐私确认与候选资格；当前项目尚未实现数据导出和微调，不能说已经形成 SFT 数据流水线。
