# 解读等待进度动画设计

## 目标

在咨询流程的“正在生成解读”阶段提供持续、柔和、可感知的等待反馈，避免用户在本地模型长时间没有输出时误以为页面卡死。

## 交互设计

- 进度动画从进入 `generating` 状态开始显示，直到生成完成、失败或用户停止生成为止。
- 采用不确定进度条，不显示百分比，避免暗示后端并不存在的精确完成度。
- 标题保持“正在生成解读”，补充状态文字“正在分析牌面并组织回答，请稍候…”。
- 流式生成的文字继续显示在进度条下方；第一段文字出现后，进度条仍保留到全部完成。
- 原有“停止生成”按钮保持不变。

## 视觉设计

- 使用现有 `--accent`、`--panel-line` 和表面色变量，不新增独立高饱和配色。
- 轨道使用低透明度边线色，活动条使用低透明度强调色。
- 活动条以约 1.8 秒的缓动动画横向循环，宽度适中，不闪烁、不跳变。
- 组件宽度跟随内容区域，并在窄屏下自然收缩。
- 在 `prefers-reduced-motion: reduce` 下关闭位移动画，改为静态柔和高亮。

## 结构与可访问性

- 生成面板增加独立的进度状态容器。
- 状态容器使用 `role="status"` 与 `aria-live="polite"`。
- 进度轨道使用 `role="progressbar"`，不设置 `aria-valuenow`，表示无法确定百分比。
- 动画元素标记为装饰性内容，避免屏幕阅读器重复朗读。

## 状态与异常处理

- 进入非 `generating` 状态后，现有渲染流程会移除进度组件，不保留计时器或额外状态。
- 停止生成、请求失败和正常完成均沿用现有状态迁移与错误提示。
- 该功能只提供视觉反馈，不改变流式请求、取消请求或后端协议。

## 测试

- JavaScript 测试验证生成状态包含状态文字、进度条语义和停止按钮。
- CSS 合约测试验证轨道、活动条、循环动画和减少动态效果规则。
- 运行全部 JavaScript 与 Python 测试，确认咨询流程及后端不回归。

## 范围

- 本次仅调整“正在生成解读”页面。
- 不为“正在保存”页面增加进度条。
- 不增加百分比、预计剩余时间或虚构的生成阶段。
- 修改保留在本地分支，未经用户明确要求不推送远端。
