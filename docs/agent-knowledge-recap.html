一眼看懂：这个项目用了哪些知识

前端界面
HTMLCSSJavaScript

页面结构、按钮、面板、主题切换、保存记录、调用后端接口。对应文件：Three.html、admin.html、js/*.js、css/*.css。

3D 交互
Three.js纹理动画循环Raycasting

78 张牌在 3D 场景中排列、滚动、悬停、翻面。核心是场景、相机、灯光、材质、贴图和每帧渲染。

手势识别
MediaPipe Hands摄像头状态机

摄像头检测手部关键点，再把 OPEN、POINT、PINCH、FIST、TWO_FINGER 映射成“开始牌阵、指向、拿牌、确认、滚动”。

后端与数据
PythonHTTP APISQLiteJSON

server.py 提供本地接口，data/tarot.sqlite3 保存历史记录、卡牌、AI 解读、设置和 Agent trace。

LLM 解读
OllamaOpenRouter 回退PromptSSE 流式输出

interpret_service.py 把牌阵变成提示词，调用本地或云端模型，边生成边推给页面，并把结果存入数据库。

RAG 与 Agent
Embedding向量相似度结构化输出Trace

interpret_rag.py 从牌义语料中检索相关内容；interpret_agent.py 做 classify、retrieve、generate、critique，并把每一步写进 agent_steps。

基础学习路线：8 到 10 周

第 0 周

先把项目跑起来，建立“整体感”

目标不是马上理解全部代码，而是知道一个用户动作怎样从浏览器进入后端，再回到页面。

  • 运行 python server.py，打开 http://localhost:8080/Three.html 和 /admin.html。
  • 完成一次抽牌、保存、到后台查看记录。
  • 打开浏览器开发者工具，看 Network 里出现的 /api/readings 请求。

小练习：在 README 里画一条自己的流程线：点击保存按钮 -> 前端发 JSON -> 后端写 SQLite -> 后台读出来。

第 1 周

Web 基础：HTML、CSS、JavaScript

你先要能看懂按钮、下拉框、事件监听、DOM 更新和样式变量。这个项目没有复杂前端框架，所以很适合从原生 Web 入门。

  • HTML：元素、表单、按钮、图片、脚本加载。
  • CSS：选择器、布局、主题变量、响应式宽度。
  • JavaScript：变量、函数、数组对象、事件、fetch()、localStorage。

小练习：给主页面加一个“当前控制模式”的小状态文本，并让它随鼠标/摄像头模式变化。

第 2 周

Three.js：为什么卡牌能在网页里“立起来”

Three.js 的核心模型是：Scene 放物体，Camera 看场景，Renderer 把它画到 canvas。卡牌就是带图片纹理的平面或薄盒子。

  • 先理解 Scene、Camera、Renderer、Mesh、Material、Texture。
  • 再看动画循环：每一帧更新位置、旋转、缩放，然后渲染。
  • 最后看交互：鼠标指向哪张牌，通常靠 raycaster 判断。

小练习：让某张被悬停的牌除了放大，还轻微发光或上浮。

第 3 周

后端 API 与 SQLite：保存记录是怎么发生的

这个项目的后端很朴素：Python 标准库处理 HTTP，SQLite 做本地数据库。学它能帮你理解绝大多数小型本地应用。

  • HTTP 方法：GET 读取，POST 创建，DELETE 删除。
  • JSON：前后端交换数据的格式。
  • SQLite：表、主键、外键、索引、查询。

小练习：给 readings 增加一个备注字段，从前端保存到后台显示。

第 4 周

LLM 基础：模型不是“懂项目”，它是在按上下文生成

你要掌握的不是神秘概念，而是几个工程问题：给什么上下文、要求什么格式、失败时怎么办、如何把生成过程流式显示。

  • Prompt：系统指令、用户问题、项目上下文、输出风格。
  • Token：模型读写文本的单位，影响成本、速度和长度。
  • Temperature：低温更稳定，高温更发散。
  • JSON mode：让模型输出机器可解析的结构，而不是随口一段话。

小练习：复制一次 AI 解读请求，把 prompt 中的风格改成“更简洁”，观察输出怎么变。

第 5 周

Ollama 与流式输出：本地模型怎样接进项目

项目优先使用本地 Ollama，这意味着用户的牌阵和问题可以留在自己的机器上。浏览器看到的逐字生成效果来自 SSE 或类似流式协议。

  • 理解 localhost:11434 是本地模型服务。
  • 理解 /api/chat 的 streaming JSON 行。
  • 理解后端如何把模型生成的片段继续推给前端。

小练习：在解读面板显示“本次使用模型：ollama:qwen2.5:7b”或云端模型名。

第 6 周

RAG：让模型先查资料，再回答

RAG 的核心是“不要只靠模型记忆”。这个项目把 78 张牌的正逆位含义做成语料，再按抽到的牌和用户问题检索相关内容，塞进 prompt。

牌义语料->Embedding->SQLite 向量缓存->按牌过滤->按问题相似度排序->注入 Prompt
  • Embedding：把文本变成一串数字向量。
  • Cosine similarity：比较两个向量方向是否接近。
  • 两阶段检索：先确保牌是对的，再让问题决定角度。

小练习：给语料增加一个“金钱/财务”场景字段，再让解读在财务问题中优先引用它。

第 7 周

Agent：不只是一次模型调用，而是一条可检查的工作流

这个项目的 Agent 很适合作为入门，因为它没有一上来做复杂多智能体，而是四步稳定流程。

classify->retrieve->generate->critique->persist trace
  • classify：把问题归类成 career、relationship、growth 等。
  • retrieve：根据牌和问题取回参考资料。
  • generate：真正生成解读，并流式返回。
  • critique：让模型自检是否跑题、漏牌、太空泛。
  • agent_steps：把每一步输入摘要、输出 JSON、耗时、错误都存下来。

小练习：在 Admin 页面加一个 Trace 面板，展示 classify 的 topic、retrieve 的条数、critique 的 score。

第 8 周

测试、可观测性与工程习惯

会调用 LLM 不等于会做可靠产品。你需要知道怎么验证 API、数据库迁移、降级逻辑、编码问题和用户取消请求。

  • 单元测试：已有 tests/test_server.py 可以作为入口。
  • Trace：出问题时看每一步，而不是猜模型在想什么。
  • 降级：Ollama 不在、embedding 模型缺失、JSON 解析失败时，主流程不能崩。
  • 编码：中文在 Python、SQLite、HTTP、PowerShell 中要坚持 UTF-8。

小练习：写一个测试，模拟 classify 失败，确认解读流程仍然能继续。

第 9+ 周

扩展方向：从这个项目走向通用 Agent 应用

当你能看懂这套流程，再学 LangChain、LlamaIndex、OpenAI Agents SDK 或向量数据库会轻松很多，因为你已经知道这些框架在帮你封装什么。

  • 把 SQLite 向量缓存换成 Qdrant、Chroma 或 pgvector。
  • 把 critique 结果用于自动重试或提示词优化。
  • 增加工具调用：例如“查历史牌阵”“统计某张牌出现频率”。
  • 做评估集：固定 20 个问题和牌阵，对比不同 prompt、模型、RAG 策略。

Agent 和 RAG 的最小理解模型

普通 LLM 调用

把牌阵和问题直接塞给模型，模型生成一段文本。简单，但容易漏牌、跑题、风格不稳定。

RAG 调用

先从牌义语料中检索相关内容，再让模型基于资料回答。优点是更稳、更可控，也更容易解释“答案从哪里来”。

Agent 工作流

把一次回答拆成多个可记录步骤。模型有时负责分类，有时负责生成，有时负责审查；系统负责流程、存储和失败处理。

这个项目的 Agent 为什么适合作为入门

设计点项目里的做法你要学到的通用能力
按需启用 只有用户写了问题，才跑完整 Agent；没有问题就走快速路径。 不要为了“像 Agent”而浪费模型调用。流程要服务用户任务。
结构化输出 classify 和 critique 要求 JSON，并把 topic、intent、score 等字段规范化。 让 LLM 输出能被程序消费的数据，而不只是自然语言。
可观测性 每一步写入 agent_steps，包括耗时、输入摘要、输出、是否成功。 调试 Agent 要看 trace，不要只看最终答案。
优雅降级 分类器失败给默认分类，embedding 不可用回退到牌义匹配，critic 失败不影响用户看到答案。 AI 组件会失败，产品不应该跟着崩。

按难度递进的项目练习

入门级

  • 改一个主题色，并确认主页面和后台都生效。
  • 给后台记录列表增加“解读次数”。
  • 把每日一牌页面的文案改得更清楚。

进阶级

  • 给 AI 解读增加第三种语言或新的风格。
  • 把 RAG 状态显示到 Admin 设置页。
  • 为 /api/interpret/<id>/agent-trace 做一个可视化面板。

挑战级

  • 做一个 20 条固定问题的评估集，比较不同模型和 prompt。
  • 让 critic 分数太低时自动重试一次，并把两次 trace 都保存。
  • 把用户历史牌阵作为可选记忆，做“最近 30 天主题趋势”。

学习顺序建议：先能改 UI 和 API，再碰 RAG 和 Agent。否则很容易被“模型术语”压住，其实很多问题只是普通工程问题。

哪些暂时不用急着学

  • 从零训练大模型：这个项目是调用已有模型，不需要先学预训练。
  • 复杂多 Agent 协作：先理解单条 Agent workflow，再看多 Agent。
  • 微调 fine-tuning：当前更需要 prompt、RAG、评估和数据质量。
  • 大型云架构：项目优先本地运行，先学清楚浏览器、Python、SQLite、Ollama 的闭环。
建议使用方式：每学一周，就回到项目里做一个小改动。只看课程不碰代码，很快会忘；只改代码不补概念，又会不知道自己在改什么。
